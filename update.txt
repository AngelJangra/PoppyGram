1. WHAT IS POPPYGRAM?
---------------------
Next.js 14 + Supabase + Telegram hybrid app with two halves:

A) ADMIN CONSOLE (pages/index.tsx)
- Password-gated dashboard (ADMIN_PASSWORD_HASH, 24h signed cookie).
- Manages Telegram USER accounts (MTProto StringSessions).
- RULE: all MTProto runs in ADMIN BROWSER via GramJS. Vercel never
  creates TelegramClient. /api/tg/* returns 410 on purpose.
- Browser scheduler: while dashboard open, browser polls /api/ping-all
  for due accounts and pings one by one. Closing browser stops pings.
- Features: health, accounts, add/remove/toggle-ping, ping, hard-reset
  (archives to account_session_backups), service-chat reader (777000),
  send-message, settings (global_credit, ping_interval_minutes),
  export/import, logs, sign-out-all.

B) TELEGRAM STORE BOT (pages/api/bot.ts webhook on Vercel)
- Real file store: admin uploads Telegram document, bot stores only
  file_id + name + price + description in store_products. Binary stays
  on Telegram servers.
- Wallet per user (bot_users.credit). New users start 0, get
  global_credit (default 100) once after /auth.
- Owner = @drangeljangra (hardcoded + seeded). /addadmin @user adds more.
- Admins UNLIMITED; normal users pay per file; failed delivery = refund.
- Hybrid /auth: bot collects phone, issues 10-min ticket
  (bot_login:{token}, AES-GCM encrypted), user opens /botlogin?t=TOKEN,
  browser does sendCode/signIn/2FA (password never leaves browser),
  POSTs session to /api/bot-verify which saves accounts + marks
  bot_users.auth_verified=true.

Tables: accounts (permanent), account_session_backups, settings (KV:
bot_state:{chat}, bot_login:{token}, store_upload:{chat}:{user},
global_credit), bot_users, bot_admins, store_products, store_purchases,
processed_updates (idempotency), audit_logs.
RPCs: purchase_store_product, claim_free_credits (24h), change_bot_credit.

7. BUGS FOUND AND FIXED WHILE BUILDING v3.8.0
---------------------------------------------
[B-1] Photos were dropped by the webhook before routing
- The /api/bot entry point only accepted messages where text was a string
  or a document was present, so any photo message was answered with
  {"ok":true,"ignored":true} and never reached the handler. Photo uploads
  and the new /editphoto step were unreachable.
- Fix: the filter now also accepts messages that carry `photo` or a
  `caption`.

[B-2] Caption-only messages were ignored
- A document/photo sent with only a caption and no text was filtered out
  earlier in some paths. handleMessage() already read `msg.caption`, so
  those messages now route normally.

[B-3] An earlier single-step edit path left a product file-less
- An experimental edit flow wrote name/price/description without a
  file_id, so a Telegram file_id could end up NULL and downloading that
  product would fail even though the row looked valid.
- Fix: updateProduct() only ever writes the file fields when a real
  file_id is supplied, so a metadata-only edit can no longer damage an
  existing file. Any product created during that experiment should be
  re-attached once with /editproduct ID -> 📎 Replace file (or option 5
  caption) to restore its file.

[B-4] /start or /help wiped an in-progress edit session
- The central "a new command cancels the previous flow" guard also ran
  for /start, /help, /support, /store, /balance, /products, /users,
  /status and /admin, so tapping Help in the middle of an edit silently
  destroyed the pending action.
- Fix: those navigation commands (plus /editproduct and /addfile, which
  re-create their own state) are excluded from the guard. Real state
  changes - /auth, /cancel, /profile and friends - still reset everything.

[B-5] "/unknown command" for a mention with arguments
- args() sliced the raw text, so "/product@PoppyBot 3" returned
  "@PoppyBot 3" as the first argument. /product worked only by accident
  because it strips "@" manually, while other commands could misread it.
- Fix: args() now strips the @BotName suffix itself, so every command
  works identically in private chats and in groups.

[B-6] A product with a nested <code> inside <b> broke the edit card
- The edit card wrapped the product name and its ID in markup that put a
  <code> tag inside a bold tag; Telegram rejects part of that nesting.
- Fix: the card now renders the name in <b> and the ID in <code>
  separately.

PART B - WEB APP LOGIN: TELEGRAM WIDGET REMOVED, /weblogin ADDED
==============================================================================

 WHY
 Telegram's Login Widget requires a domain registered with /setdomain, fails
 silently behind Vercel preview URLs, and any mismatch shows "Bot domain
 invalid". The new flow needs no BotFather domain at all.

 NEW FLOW
   1. User opens https://poppygram.vercel.app/app
   2. The login card shows the 3 steps: open @<store bot> -> send /weblogin
      -> copy the Telegram ID + secret code.
   3. /weblogin (private chats only) replies with:
        Telegram ID:  <uid>
        Secret Code:  <8 hex chars>
      stored ENCRYPTED in the settings table under key `weblogin:<uid>` as
      {tg_user_id, password, expiresAt}; valid 15 minutes, single use.
   4. /api/web/login {tg_user_id, password} verifies the code, deletes the
      ticket, and sets the signed wa_session cookie (unchanged format).
   - Entering a new /weblogin code overwrites the previous one.
   - The old widget payload {id, first_name, auth_date, hash} is still
     accepted as a fallback, so nothing that already works breaks.

 FILES
   lib/botFlow.ts          generateWebLoginPass(), verifyWebLoginPass(),
                           deleteWebLoginPass()  (AES-256-GCM at rest,
                           one-time delete, 15-min TTL, expired rows cleaned)
   lib/bot.ts              `weblogin` added to BOT_COMMANDS
   pages/api/bot.ts        /weblogin handler + /weblogin added to /help
   pages/api/web/login.ts  password-first verification, widget fallback kept
   pages/api/web/session.ts comments only (bot username still returned)
   pages/app.tsx           widget script removed; BotLogin form (ID + code,
                           2-field validation, inline error, busy state)
   styles/support.css      .wa-login-form / steps / field / input / code /
                           error / submit / note (dead widget CSS removed)
   WEBAPP_INTEGRATION_GUIDE.md  login section rewritten + login.ts table row

 VERIFIED LOCALLY (mock PostgREST + real lib modules + live next dev)
   API route (/api/web/login): 9/9 PASS - valid code -> 200 + signed
   wa_session cookie (HttpOnly; SameSite=Lax), replay -> 401, wrong code
   -> 401, malformed ID -> 400, missing credentials -> 400, GET -> 405.
   Ticket lifecycle: 13/13 PASS - 8 hex chars, ~15-min TTL, encrypted row
